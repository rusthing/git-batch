gb git-batch UI 原型评审 · v0.1

三种批量 Git 管理界面,
选一个作为 git-batch 的起点

目标是用 Rust + Tauri 2 做一个跨平台的专用 Git 批量管理工具,交互参考 IntelliJ IDEA 的 Git 工具窗口,但把"一次操作多个仓库"作为一等能力。下面三款原型使用同一组 mock 数据,可直接点开体验。

Tauri 2 + React + Vite macOS / Windows / Linux 8 个仓库 · 含冲突 / 落后 / 暂停场景 三款均为静态可交互原型
打开原型 ↗
AIDEA 工作台

沿用 IntelliJ 的肌肉记忆

左侧仓库树 + 中间变更/提交记录 + 右侧 diff,顶部工具栏直接作用于勾选的仓库。最接近日常在 IDEA 里管理单个仓库的体验,迁移成本最低。

三栏布局提交图文件级暂存批量作用于选中项
适合:从 IDEA 迁移的用户体验 →
打开原型 ↗
B仓库矩阵

把所有仓库摊平成一张表

表格式总览,分支、变更数、领先/落后、最近提交同屏对比;勾选后底部浮出批量操作条,右侧抽屉看单个仓库详情。信息密度最高,批量路径最短。

表格总览多选批量条详情抽屉任务日志坞
适合:20+ 仓库的工作区体验 →
打开原型 ↗
C执行计划

先预览风险,再生成执行队列

把批量操作拆成"选仓库 → 选操作 → 看风险预览 → 生成队列",执行时逐仓库展示进度,可暂停、取消、重试失败项。最稳妥,也最像一次正式发布操作。

风险预览执行队列暂停 / 重试仅快进合并
适合:多人协作 / 谨慎批处理体验 →

取舍对比

没有绝对优劣,取决于你更看重"顺手"还是"可控"

布局模型仓库树 + 变更/日志 + diff 三栏单张聚合表格 + 详情抽屉仓库清单 + 操作编排 + 执行队列

单仓库深度操作强:文件 diff、暂存、提交图完整中:抽屉内可看文件与提交中:右侧详情偏只读
实现成本中:三栏 + 提交图渲染低:表格与批量条为主要工作量高:队列状态机与并发控制
推荐指数★★★☆★★★★★★★★
我的建议:以 B 为主框架(仓库总览是批量工具的核心),把 A 的"变更 / 提交记录 / diff"三栏下沉为单仓库详情页,再吸收 C 的"执行前预览 + 队列进度"作为批量操作的确认层。这样既保留 IDEA 的单仓库深度,又让批量路径足够短。
